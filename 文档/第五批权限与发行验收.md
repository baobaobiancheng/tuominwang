# 第五批：权限、容量、删除与私有发行

更新日期：2026-09-23。私有 AI 模型经用户明确要求另行确认，本次没有下载、调用或把它计为已完成。

## 已实现并验证的权限与生命周期

- 组织所有者、管理员、成员；管理员创建受管理账号、调整角色和启停账号。组织角色不隐含项目资料权限。
- 项目按十项能力独立授权：原件查看、人工复核、导出、映射查看/创建、还原、模型调用管理、成员管理、导入、词表管理、删除。
- API 同一事务内锁项目、重新检查权限、再执行操作；不是仅靠前端隐藏按钮。复核保留现有已确认假名不强制泄露映射表。
- 只授予导出/还原也能操作，不需要先取得原文查看权限。上传成员只可读取自己的上传记录，除非另外授予原件查看权限。
- 撤权后拒绝新操作、取消排队任务、终止正在运行的解析/识别，提交前再次检查授权。停用账号结束会话。已签发链接继续按原期限使用。
- 桌面组织管理、项目成员、原件只读、独立功能控制、操作记录、材料配额与明确删除入口。页面不展示对话、工程取舍或研发进度。
- 默认组织容量 10 GiB/10,000 份原始材料，可由组织管理员修改；额度跨项目原子计量。派生资源/模型不计入该逻辑配额，部署仍需监控实际磁盘。
- 删除绑定当前版本：清除该材料数据库内容、复核快照、任务、上传记录中的对应条目；保留不含原文的审计。其他材料不受影响，项目共享假名映射/词表不会连带删除。
- 删除文件通过持久队列完成，等待已签发链接到期；新写入对象记录所属材料，涵盖取消/崩溃未发表的对象。迁移前无法识别归属的历史孤立文件不会被猜测删除。

实测修正了几项仅静态配置检查没有发现的问题：生产依赖裁剪需要非交互模式；YAML 临时目录参数需要整体引用；Nginx 的全部临时路径必须放到可写 tmpfs；本机纯 internal 网络未发布宿主端口，因此只给 Nginx 增加入口网络；Docker 目录排除规则重新收紧，避免开发脚本进入镜像。所有修正后重新执行了上述容器检查。

断网运行时发现 ONNX Runtime 初始化遥测提示；现已在原生库初始化前强制关闭，并覆盖本机主进程、任务线程和容器，依据 [官方隐私说明](https://github.com/microsoft/onnxruntime/blob/main/docs/Privacy.md)。再次断网推理没有遥测初始化提示。网络隔离依然保留，不把环境开关当成网络出口控制的替代。

`pnpm audit --prod --json` 本轮结果为 0 个已知漏洞（145 个生产依赖、34 个可选依赖）；这不是无漏洞证明，也不替代持续更新或独立安全审计。
