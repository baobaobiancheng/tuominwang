## 3. 组件候选与可行性边界

所有版本在 R0 建立锁文件、镜像摘要和模型哈希后锁定；不把网页的 latest 当作可复现版本。许可证要逐依赖、权重和分发方式核对，不从运行框架许可证推导模型权重许可证。

| 职责 | 候选 / 已知能力 | R0 必须证明的内容 |
|---|---|---|
| API 与共享契约 | [Fastify](https://fastify.dev/docs/latest/Reference/Validation-and-Serialization/)提供 Schema 校验/序列化；[Drizzle](https://orm.drizzle.team/docs/transactions)提供事务接口 | 同一契约驱动请求、响应和 worker 校验；Schema 仅来自受信代码，不接受用户上传可执行校验规则；事务内租户上下文不能串到连接池下个请求 |
| 单元与浏览器测试 | [Vitest](https://vitest.dev/guide/)、[Playwright Test](https://playwright.dev/docs/library) | Node 与框架版本兼容；实际 API＋PG＋worker 集成测试，不能只 mock 队列 |
| PDF 读取/预览 | [PDF.js](https://github.com/mozilla/pdf.js)作为读取和渲染候选 | 字体、旋转、CropBox、跨栏、扫描混排、坐标转换；读取能力不等于脱敏回写能力 |
| PDF 生成 | [pdf-lib](https://github.com/Hopding/pdf-lib#limitations)明确不提供普通页面文本删除/编辑 API | 可评估用于从已清理像素生成全新 PDF；不得将 drawRectangle 当作真删除。保留文本结构的安全回写仍是 R0 技术阻断项，不能靠一条库依赖宣布解决 |
| DOCX | ZIP/XML 白名单遍历及对象级修改；保留 Word 容器锚点，不用纯文本提取结果重新拼接冒充原格式 | 页眉页脚、文本框、修订、关系、嵌入对象、图片及属性覆盖；未知载荷阻断/明示降级，不能复制未检查 ZIP 条目 |
| XLSX/CSV | [ExcelJS](https://github.com/exceljs/exceljs)作为表格读写候选，另用包结构检查补足覆盖清单 | 输出新值快照，不回写未知对象/外链/公式；公式缓存是否存在不代表可信，需来源与明确导出前提；测试隐藏表、共享字符串、批注、合并单元格 |
| OCR | [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR)现成引擎；[RapidOCR](https://github.com/RapidAI/RapidOCR/blob/main/docker/README.md)作为 ONNX 运行路径候选 | CPU/arm64 实际可运行、中文和印章覆盖、字符/行坐标、低质扫描；不以 OCR 整行框冒充逐字位置 |
| 中文 NER | [bertspan4ner-base-chinese](https://huggingface.co/shibing624/bertspan4ner-base-chinese)可列候选；模型卡标注 Apache-2.0 | 权重来源及依赖核验；其 Span 输出不直接等于标准 token-classification 接口；ONNX 导出、TS 解码和坐标映射须比对参考结果。论文/模型卡成绩不能代替法商财税材料成绩 |
| NER 候选排除误判 | [CKIP 模型卡](https://huggingface.co/ckiplab/bert-base-chinese-ner)标注 GPL-3.0 且主要面向繁体中文 | 不能误记为 MIT 模型、不能默认对简体法律材料达标；未经发行兼容性核验不纳入默认包 |
| L3 | Codex CLI 为已批准开发基线；本机私有候选 Ollama，Linux GPU 有需求再比较 vLLM | 同一任务/金标/切分；账号额度和私有性能分别记录。没有选定权重、量化与实测前，不宣布私有模型选型完成 |

原格式安全导出是本项目最大的可行性风险。允许的降级沿用产品设计：用户明确确认后，从已处理内容生成扁平 PDF；不静默降低能力，也不把所有文件均强制栅格化作为 R1 原格式能力的替代。只有降级路径跑通时，应报告“R0 部分通过，R1 未满足”。

## 4. 架构和任务契约评审

以下流程已按 D1、D6—D8 的用户选择更新；D5 恢复部分仍单独标为待确认，不作为已批准要求。

```text
浏览器 --认证/版本--> API --短事务--> PostgreSQL（项目、权限、任务、版本）
                         |                         |
                         |受控文件引用             |领取租约、续期
                         v                         v
                     私有文件存储 <------------- TS worker
                                                |
                               解析/OCR -> L1/L2/L3 -> 候选
                                                |
浏览器复核 -> 决策版本 -> 导出快照 -> 私有文件（待核验）
                                                |
下载请求 -> 当前权限/版本检查 -> 实际产物残留及完整性检查
                                                |
                         通过 -> 签发绑定不可变文件的短时链接
                                                |
                            有效期内允许访问；到期拒绝
```

- 模块拟分 `apps/web`、`apps/api`、`apps/worker`；`packages/contracts` 只放 Schema 与数据定义，`packages/core` 放裁决/映射/状态机，`packages/adapters` 放格式、模型、文件存储适配器。web 不引入数据库和密钥实现；解析器不持有全租户凭据。
- 数据表最少覆盖组织/成员、项目、文档与版本、覆盖单元、识别运行/候选、复核事件、实体/映射版本、任务/attempt、发布快照/产物、外发授权、审计及删除记录。JSONB 放扩展证据，外键/权限/状态仍为明确列。
- 所有子对象带 tenant/project 关联；复合外键及唯一约束禁止跨项目挂接。同名不同实体不因字符串相同自动合并。映射原值加密；加密上下文包含租户、项目、字段和版本。
- API 和 worker 使用非超级用户、非 BYPASSRLS 的受限角色；迁移角色隔离。应用鉴权与 RLS 均测试；租户上下文仅在事务作用域设置，缺上下文拒绝访问。
- 领取任务使用短事务与 SKIP LOCKED，业务任务与入队记录同事务提交。推理/解析不能占用数据库长事务。租约带单调递增代次，写回必须同时匹配任务、代次、状态和输入版本。
- 外部派发不明也按配置有限自动重试，每次重新检查外发授权并记录 attempt。取消不能撤回已发送内容，UI 如实显示；多实例领取不等于端到端 exactly-once，也不保证外部额度只扣一次。
- 产物先写唯一私有路径，再由下载前核验控制放行。半文件、找不到版本或哈希不符必须拒绝；签发链接前再次检查当前权限和有效版本。链接绑定不可变对象，不能以同路径覆盖替换内容。文件元数据与生成任务可正常落库，但不额外建设已拒绝的事务发布协议。
- D5 待确认：如果保留备份恢复且要求不复活已删数据，需要独立删除/撤权记录；如果一期取消备份恢复，则不建立这套恢复系统。不能将两种方案同时实现。
- 用户项目备份与系统灾备的首版范围正在确认；未获选择前不实施备份恢复或自动清理。若保留恢复，包内租户、会话与运行中任务不能直接成为当前权限。
- 文件、映射及配置秘密按版本化密钥加密；私有部署密钥由挂载 secret 提供，不放镜像或密文包。备份密钥恢复演练先于生产使用；日志排除原文、完整候选、模型请求及凭据。
- 登录、复核、下载、删除、外发及还原都在服务端鉴权；Cookie 会话用安全属性并校验跨站写请求。预览隔离、禁止宏脚本/外链；提取进程禁出网，不挂整个工作目录。
- 不复用跨租户明文识别缓存。任务进度与失败统一使用稳定错误码、定位和下一步动作；不能通过任务完成率 100% 隐藏某层未执行。

建议在 `packages/core/job-state.ts` 与 `packages/core/download-verify.ts` 实现时写入上述状态/核验流程注释。文件名是计划，不是现有代码。

## 5. 代码质量与性能评审

### 代码质量

本轮发现 D1 一项设计缺口；没有现存代码，因此不报告虚构的重复函数或代码覆盖率。

- 共用一套候选 Schema、UTF-16 文本跨度契约及原文件锚点；转换层记录模型 token/Unicode 标量偏移的换算，禁止各层自行猜位置。
- 区分空候选、解析失败、模型未执行、不确定和真正通过；以可区分的返回类型表达，不用 `[]` 代替全部错误。
- 规则执行限制长度与耗时；用户正则不在 API 主线程无限执行。名单是数据，不允许上传可执行 Schema/JS。
- 原文版本不可变，OCR 改字新建版本；不得原地改文本后继续使用旧高亮/审批。规则、NER、L3 只返回候选，不各写一套替换器。
- 预览与执行共用决策快照；安全复查必须重新打开实际导出字节，不能只复查内存中的预览。

### 性能

本轮发现 D3 一项设计缺口。没有 SQL、运行实例或基准，不把潜在 N+1 查询、内存问题写成已复现性能缺陷。

- 页级处理、分批写候选，浏览器仅渲染可见页与候选；不把 1000 页图像一次解码进内存。
- 任务索引按状态/可执行时间、项目索引按租户/项目/更新时间规划；列表分页并批量聚合状态，不每个文件再查一次数据库。R0/实现阶段用真实 SQL 执行计划核验。
- 本机重解析/OCR/L3 先用一个资源槽，不仅限制每个 worker 的并发。心跳与任务控制不与阻塞解析共享事件循环。
- 字节限制不足以防解压炸弹；流式计算解压总量、条目数、图像像素和单元格数，达到限制立即阻断并回收临时对象。具体阈值在 R0 样本统计后锁定，不能仅写“有限额”。
- 阶段超时和重试上限逐类配置；长任务持续心跳但不能无限续命，内存或磁盘预算耗尽清晰失败。存储不足阻止新任务，不删除历史项目。
- 基准分别测文本 PDF、扫描 PDF、混合 PDF、DOCX 表格与 XLSX；记录页数/对象数、硬件、模型、冷/热启动、排队、各阶段 p50/p95、峰值 RSS、临时磁盘量及取消回收耗时。
- 只比较同一模型/精度/输入下的运行引擎性能；Codex CLI 云端基线不作为本机私有性能承诺。

## 6. 测试评审与失败模式

现状：没有工程测试框架或实现。下图均为 GAP/计划，绝非 TESTED。下表 14 个路径族均需实现测试；不能将 0/14 当成代码行覆盖率。

```text
用户上传 [→E2E]
  +-- 无权/空文件/超限/伪装格式 -> 明确拒绝                T01
  +-- 合法 -> 存储/入队 -> 重复提交/断线 -> 恢复一致结果    T02
       +-- 解析/OCR -> 缺页/隐藏对象/坐标失败 -> 阻断         T03
```
