## 已实现

- L1 增加固定电话、手机号、邮箱、身份证校验、银行卡 Luhn 校验、统一信用代码 MOD31 校验、案号格式、带字段提示的对公账号/护照号；CSV/XLSX 表头提示；项目精确匹配词表。校验通过不是号码真实存在或主体已核验。
- 候选携带来源代码及原文 UTF-16 位置。同跨度同类型合并证据，不同类型或重叠范围保留待人工判断；不比较跨模型置信度自动覆盖。客户端不能伪造识别来源，新补标标为人工来源。
- 项目词表加密保存、版本冲突保护。更新词表取消活动任务、使既有文档进入需重新识别状态；不自动沿用旧决定。已签发链接仍可用至到期，新链接和新导出受版本及快照阻断。
- 重新识别创建新版本；识别引擎及词表版本写入不可变快照。规则与 NER 读取同一解析文字，不逐层改写原文。
- Codex CLI 开发适配器只接受 SHA-256 固定的 12 条合成样本，不接受路径或任意输入，不接业务 API。使用空临时工作区、只读权限、禁用 shell/MCP/浏览器/插件/记忆等，外层 macOS 文件读取沙箱禁止读取整个 FDE 工作区，并先执行拒绝读取探针。使用个人已登录账号但不复制凭据。最多 3 次总尝试、每次最长 120 秒，先原子记账再调用；结构化结果必须逐字匹配唯一原文片段。它不是生产 L3 提供方。

## 中文 NER 实测

- 候选采用评审列出的 [shibing624/bertspan4ner-base-chinese](https://huggingface.co/shibing624/bertspan4ner-base-chinese)，模型卡 Apache-2.0；权重固定 `dc0de59380bcf4d42c1e9a8ff267e19e00f331f9`。参考实现 [nerpy](https://github.com/shibing624/nerpy/tree/30ff7bfef453b332e41fc25c24e5110842bd646e) 同为 Apache-2.0。
- 不是大模型替代 NER。BertSpan 的 start/end 头按参考实现离线转换为 ONNX；构建脚本使用 Python，但产品推理、任务和接口均为 TS。`torch.load(weights_only=True)`、源权重 SHA-256、严格 state dict、运行包哈希都检查。
- Node 原生 ONNX Runtime 1.30.0 CPU 推理，2 个内部计算线程；128 token 输入，126 个字符窗口、32 字符重叠；UTF-16 映射支持 emoji。单次实体识别上限 20 万字符，超限明确拒绝。既有大文件规则流程不强制开启 NER。
- 六个公开/合成参考片段的 tokenizer 与 Python 一致，最大 logit 差 `0.00001621246337890625`。本机约 1 秒完成参考推理及分段检查（不含首次加载）；断网进程实测峰值 RSS 约 669 MiB。不是生产负载/性能承诺。
- 用 OS 网络拒绝策略运行 `scripts/check-ner.ts` 成功；不访问云模型。真实 PostgreSQL/API/worker 的 NER → 新版本 → 人工复核 → TXT 下载验证通过。
- 已观察局限：`合成甲乙公司 联系13800138000` 未产生机构候选；地点可能被拆为“深圳市”“南山区”，不等于完整邮寄地址。词表与人工复核仍必要，不声称领域准确率通过。

## 复现及未完成项
