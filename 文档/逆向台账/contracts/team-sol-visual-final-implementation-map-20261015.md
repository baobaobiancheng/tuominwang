## 后续实施与验收边界

1. `get-ocr-page` 的 PDF buffer 缺缓存即重识别仍是按需链的确切差异：源 renderer 在 25635 带 fileName、ocrCacheKey、pageNumber、totalPages、pageNumbers、pdfBuffer；main 18308–18342 在 q2 miss 时以 J2 同 key 合并 forced OCR 并轮询该页。当前 `GET /ocr-text` 只读已有 page/map，`ocr-rerun` 是单独动作。最小 Web 方案是在显式授权的页读请求中仅使用服务器已验证原件和 revision，缺页时复用现有 OCR worker、同 doc/revision/page singleflight，完成后再读页；不能接受客户端任意 PDF buffer。此方案未实施，也不建议在当前冻结与全 API 运行中插入。
2. 源项目审计 `Kf2` 以非空 text/type 启动；`Rf2` 同步当前草稿后遍历 ready 材料并列 skipped；`Pf2/Tf2` 按格式找到匹配后分 same/other/uncovered；`av2` 可单项或全部 add、replaceOther，成功后刷新注册与审计。当前项目 route 已复用 `entity-seeds` 与 `checkKnownEntities`，且在 SQL 事务锁与 CAS 中批量补录 pending；需要在此基础上增逐项结果与操作，勿重建第二套全项目扫描。
3. PDF 右侧实体跨页修复已有 `focusRange` 代码；仍须新的两页 PDF Edge 操作证明。项目纠错 preview/apply 也已实现，旧“无项目范围”文字失效。
4. 当前完整 API 串行尚在执行，fresh 全 Edge 尚未通过；旧指南图、历史 PASS、测试源码和实际 API 分层记录。印章公开集 F1 20.21% 仅是当前质量边界。
