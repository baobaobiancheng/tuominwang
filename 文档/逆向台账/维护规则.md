# 台账维护规则

## 唯一事实源

人工只编辑 `ledger.json` 的接口、链路、证据、待办和事件。`maintain.py` 仅校验并生成视图，不读取密钥、不执行竞品代码、不调用接口，也不修改应用。

从项目根目录运行：

```sh
python3 文档/逆向台账/maintain.py
python3 文档/逆向台账/maintain.py --check
```

第一条生成 CSV、README、变更日志及校验 JSON；第二条只读校验，发现派生文件过期时返回非零。校验覆盖稳定 ID、重复入口、引用文件/行列、历史 IPC 完整覆盖、REA observation 保留、链路引用、空证据、状态值和事件引用。它不能证明源码解释正确或功能已运行。

## 每次迭代的追加步骤

1. 搜索既有 `kind + name`，已有入口补证据，不重复建条目。新增 ID 为 `kind + '-' + sha256(name UTF-8)[:12]`，不得按排序重新编号。
2. 记录确切来源版本、路径、行列或静态产物。已有 REA observation ID 保留；新增分析来源明确标注人工追踪、官网说明、运行录制或我方测试。
3. 单独修改三个维度：静态深度、竞品运行状态、我方实现状态。只有同一条目具备相应证据时才提升。测试总数、截图、HTTP 200、启动成功都不能批量提升接口状态。
4. 更新链路归属；仅根据命名空间划分时保留“命名线索待核”。只有已读上下游调用关系才改为“已追踪局部关系”。完整链路需覆盖输入、调用、处理、存储/副作用、输出、失败恢复每段。
5. 写明剩余待办、差异和不适用理由。仍未评估的入口保留 I0，不能为让完成率好看而改成已完成或不适用。
6. 在 `events` 追加一个新事件：日期、唯一事件 ID、动作、变更摘要、所有受影响的接口/链路 ID、验证结果。状态升级在摘要写明“旧状态→新状态”和支持证据；回退也需记录。
7. 运行生成及只读校验。交付时报告新增、补证、关闭待办、仍缺项及竞品运行边界；所有CSV/README与JSON一起更新。

## 状态使用

- S1：入口/声明观察。S2：关键契约或局部链路追踪。S3：完整静态链路逐段闭合，不能仅凭 handler 有代码就标记。
- R0：未逐项运行。R1：只有该入口/页面的实际观察。R2：该条目端到端合成材料运行有证据。R1/R2 必须增加 `runtime_evidence`，不可用我方运行替代竞品运行。
- I0：未逐项评估。I1：独立相关实现，仍有差异。I2：能力明确未实现/未启用。I3：明确不属当前对齐目标。I4：逐项实现和验证完成；需要字段、失败、权限、版本、真实输出证据，且明确仍有哪些竞品行为未可比。

我方实现与竞品运行是独立维度：实现了相似能力并不要求复用竞品代码，也不能由此推定双方效果等价。无许可证时，竞品处理链路保持 R0，继续可核验的公开资料和静态研究。

## 版本演进与历史

- 已有通道在新版本保持名称：保留 ID，追加新版本证据及事件；旧来源不删。语义变化在摘要中写清，不能拿旧运行证据证明新版本。
- 入口改名：新增 ID，保留旧条目并标 `lifecycle: retired`，新增 `replaced_by` 指向新 ID；不要物理删除历史项。
- 新发现的动态通道先保存表达式及来源，不猜测通道名。初始快照曾有 3 处未解析动态 IPC；该数字是历史状态，当前数量以 ledger.json.reference 与动态调用专项为准。发布调用点的静态集合已解析，也不能把 2 个通用桥运行时任意字符串能力改写成有界全集。
- 原始 `文档/脱敏猫IPC接口清单.csv` 是历史导入基线；新的入口追加到 JSON，不能删改基线来让覆盖校验通过。
- 引用路径相对本项目根目录。源码版本或文件变化导致行号漂移时补新证据，并保留旧快照。不要把没有保留的临时文件作为唯一证据。
- 研究资料含专有发布代码，仅作为证据；不进入应用发布镜像。不得记录许可证、会话密钥、真实业务材料或账号凭据。

## 已加入 AGENTS.md 的持续维护规则

> 每次与脱敏猫相关的逆向分析、接口/链路发现、功能对齐或验收迭代，都同步维护 `文档/逆向台账/ledger.json`：新增或补充稳定ID条目、证据、静态深度、竞品运行状态、我方实现状态、链路及待办，并追加 events。执行 `python3 文档/逆向台账/maintain.py` 与 `--check`，随改动交付生成视图。不得把命名归类当成完整调用链，不得把我方测试通过当成竞品逐项运行验证；无许可证保持相应运行未验证。

上述要求已写入项目根目录 AGENTS.md，后续每轮相关迭代均须同步维护。
