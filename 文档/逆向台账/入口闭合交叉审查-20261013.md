# 115 项入口与两处动态桥交叉审查

审查日期：2026-10-13。对象：`contracts/ui-closure-a.json`、`ui-closure-b.json` 与 `dynamic-closure.json`。全程仅解析已发布源文件，不执行竞品代码、许可激活或文档处理。

## 结论与适用范围

115 个原待核 ID 的集合核验通过：A 58 项、B 57 项，交集 0、遗漏 0、重复 0。44 项具有当前发布包前端调用或生命周期订阅，其中 `log:renderer-error` 的 renderer invoke 可达，另有两条 preload send 兜底与主进程 handle 不匹配；71 项在当前发布 renderer 没有对应调用，不能把这些保留端点描述成 71 个用户可用按钮。

两处通用 invoke 桥在此发布包的实际调用集合为 39 处、14 个字面通道；71 个无引用端点与这 14 个通道交集为 0。没有剩余未分类的已知前端入口，没有剩余非字面 invoke 调用点。这一结论限定已发布代码的静态调用集合：桥本身仍接收任意字符串和参数，没有白名单；不能宣称任意运行时输入集合有限或竞品全部功能已通过运行验收。

当前未发现需阻断这三个静态入口报告交付的未修复问题。115 项均保持完整业务契约未完成、竞品运行 R0。操作系统行为、原生组件、远端服务、磁盘失败恢复及我方功能等价性未由本次入口审查证明。

## 独立核验

- 独立从 ASAR 文件头解析 16 个 dist JS/MJS/HTML 成员，逐一比较发布字节、提取文件及 dynamic 报告 SHA-256；集合和字节一致。
- renderer 资产为 5 个文件：4 个 JS/MJS 与 HTML 入口，含补提取的 OpenJPEG fallback。两个 UI 分组及 dynamic 的对应源集合一致。此前遗漏的 fallback 只增加 typed-array.set 同名候选，不新增业务桥调用。
- 使用独立 TypeScript AST 遍历与词法变量别名展开，交叉比较 A/B 的前端可达分类；处理 `window.ipc ?? window.anbao` 等别名，重新得到 39 处 invoke、14 通道。
- 对 ASAR 其余 8563 个依赖脚本追加 `anbao` 字面筛查，命中 0；与动态专项的 ipcRenderer/ipcMain/window.ipc/electron 筛查相互补充。此处是词法筛查，不冒充依赖全语义分析。
- 人工复读高误判风险关系：rulesets.exportExcel 与 dictionary.exportExcel；workspace store.saveAs 与旧 workspace:save-as；feedback.addBatch 与 feedback:add；PDF Font.exportData 与 dictionary.export；恢复弹窗 cancel 与 auth:cancel-recovery；通用 invoke 与 preload send。未发现把同名方法或内部服务复用伪装成目标 IPC 调用的情况。
- 对回填认证、更新偏好、窗口关闭、电源恢复、OS 打开 .tmm 与许可状态分支检查输入及失败处理：报告保留失败/未确认状态，没有以 success 字段或静态注册冒充运行通过。

## 发现并修复的问题

P2：A 组最初扫描器从待验 `ui-closure-a.json.scopeIds` 读取范围，只有长度 58 检查。若报告和 census 同时替换 58 个不同 ID，单组复核无法保证仍是原来的前 58 项。已通知 A 代理，将原始 58 个 ID 固定在扫描器代码中；修改后的 `--check` 通过。B 组也将原始 57 个 ID 固定在扫描器内。独立交叉检查另比较整个原 115 项基线。

## 对抗性探针

在内存中修改报告副本，未改动证据文件。以下 7 种变化均被独立检查拒绝：

1. 删除一个接口。
2. 将一个 ID 替换成重复 ID。
3. 将一个无引用端点伪造成前端可达。
4. 删除一个动态通道。
5. 伪造源文件 SHA-256。
6. 未运行却将 R0 升为 R2。
7. 从前端资产集合移除 OpenJPEG fallback。

证据：`contracts/entry-closure-cross-review.json`，记录三个报告的 SHA-256；脚本 `contracts/cross-review-entry-closure.mjs` 可复跑。B 组范围校验另通过 458 个引用、342 个唯一源码范围。哈希/集合/负向探针证明报告与本次静态证据一致，不独立证明所有自然语言契约语义。
