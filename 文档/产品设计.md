# 通用文档脱敏工作台：产品设计

日期：2026-09-20｜流程：office-hours｜状态：APPROVED，用户于本日批准完整产品设计，进入工程评审；尚未授权生产发布。

本文件是工程设计唯一正文入口；尚无实现、性能测试或安全认证。代码未来放在 `工程/`。本目录当前不是 Git 仓库，不虚构分支、提交或发布状态。

## 1. 目标与已确认决定

面向律师、企业法务、财务税务人员以及一般企业文档处理者，提供导入、三层识别、人工复核、脱敏导出、授权还原的网页工作台。兼顾内部使用与对外销售，不针对某个内部流程定制首版。

已由用户确认：

- 网页版优先；同一产品支持私有化与公网 SaaS，先在私有化环境验收。
- 识别底座为正则规则、中文 NER、AI 语义识别；三层产生候选后统一裁决，不逐层破坏原文。
- 模型支持私有与外部 API；默认禁止外发，管理员配置不是无限制发送原文的许可。
- 完整规划包含企业组织、权限、席位、部署管理；分阶段交付不代表删除功能。
- 首版输入含 DOCX、PDF、JPG/JPEG/PNG、Markdown、XLSX、CSV、粘贴文本。
- 按风险放行；不确定、高风险与失败项不能自动通过。
- 安全画像与背景补充为第二阶段；首版保留实体、关系和证据扩展位置。
- 实现路线 A：模块化业务后端＋独立后台任务进程。当前不拆大量微服务。
- 工程补充决定：业务代码全 TypeScript，不采用 Python/FastAPI/Celery 业务后端；允许调用非 TS 的现成模型引擎及原生/WASM 库。用户已确认保持 PostgreSQL 保存任务表，独立 TS 任务进程消费，首版不引入 Redis，也不同时兼容 MySQL；选型依据见第 13 节。
- 业务框架已确认：React + Vite、Fastify、Drizzle；测试采用 Vitest + Playwright。
- 下载与重试取舍已确认：已签发下载链接允许有效期内继续访问；外部模型未知执行状态也允许有限自动重试，可能重复消耗额度；导出先保存私有文件，下载前核验。不得继续承诺旧链接即时撤销、外部调用绝不重复计费或仅凭文件存在即可下载。
- 正式部署以 Linux 容器为基线，Mac 用于开发；开发测试改用 Codex CLI 的 ChatGPT 账号额度，不要求先提供 API Key。未授权自动上传私有资料、无限额调用或安装/下载模型；API 接口保留为后续适配能力，不自动切换计费。
- 组件只用无需付费且许可证适配发行方式的开源方案；商业组件不进入候选。模型 API 调用费用与组件许可费用分开管理。
- 当前优先验证处理效果；暂不作公开注册、支付和订阅的首版交付承诺，具体理解见第 13 节。必要访问控制不因延期商业化而删除。
- 项目数据默认持续保存至用户明确删除，不设默认 30 天到期；不等于承诺无限存储空间，也不等于关闭删除能力。

用户需求证据是上述明确选择与已有样本测试，不是付费意愿证明。没有已验证的客户数量、收入、人工节省数据。不得把竞品客户宣传当成本产品需求验证。

首版实体验收清单：人名、机构及简称、地址、金额、身份证号、电话、邮箱、银行账号、证券/资金账号、统一社会信用代码、微信号、案号/公文号、车牌、网址、专利号、备案号、印章区域、人脸区域。类型命中不自动等于必须隐藏，例如金额需要结合使用目的决定。

R1 语义识别场景至少覆盖：谈判底线、未公开交易计划、诉讼策略、内部经营预算、客户关系与组合敏感事实。每类提供正例、反例及跨段落例子。无充分证据则输出不确定，而非编造敏感性。

暂不纳入：实时音视频、声纹识别、完整邮件/聊天平台连接器、CRM/ERP 深度集成、自动法律意见生成。未来六类输入体系仍保留，但不能把未来接入写成首版已支持。

## 4. 端到端职责与三层识别

处理顺序：上传与授权校验 → 文件安全检查 → 解析/OCR及覆盖清单 → 三层候选识别 → 实体/策略裁决 → 风险复核 → 生成副本 → 对实际产物复查 → 发布下载。任何阶段失败均保留具体定位和恢复动作。

| 层 | 输入与职责 | 不承担的职责 |
|---|---|---|
| L1 规则 | 原始规范化文本、字段名、名单；格式匹配、校验位、边界及上下文词 | 单靠数字格式认定商业秘密；靠表头断定全部内容敏感 |
| L2 中文 NER | 同一文本版本及结构上下文；实体边界、类型、简称候选 | 直接决定所有实体均需隐藏；将同名视为同一人 |
| L3 AI 语义 | 受控环境内的完整必要上下文，或获准外发的最小片段；识别业务秘密、关系与敏感组合 | 执行文档中的指令；自行检索公网；直接编辑原文件 |
| 统一裁决 | 合并候选、保存证据，按用途和规则确定处理动作；冲突入复核 | 简单比较三个来源不可比的置信分数，或让某一层无条件覆盖其他层 |
| 执行器 | 按已批准版本生成脱敏副本并检查 | 修改用户原件；将疑似结果当作可逆映射事实 |

L3 不只是接收 L1/L2 剩余文字：没有实体的句子也可能泄露策略。允许按风险选择处理，但必须显示哪些段落未经过 L3；要求三层覆盖的项目在 L3 不可用时不能默默降级放行。

规范化文本保留向原文件结构的双向锚点：DOCX 对象路径、PDF 页/区域、XLSX 工作表/单元格、Markdown 字符范围。识别结果绑定文件哈希、解析版本和文本版本。修改文本使旧候选失效。

每次导出绑定不可变处理快照：原件哈希、解析/OCR与文本版本、规则与名单版本、NER/LLM与提示词版本、策略、映射、人工复核记录版本、覆盖清单、导出配置及产物哈希。任一相关输入改变，受影响的候选、复核或产物校验失效；未变化且可证明无影响的结果才能复用。用户选择先保存私有文件，下载前再核验；只对核验通过的实际文件签发短时链接，不凭文件存在或任务完成放行，不临时重新生成未检查内容。已签发链接在有效期内可能继续访问旧版本，这是用户明确接受的边界。

每个候选记录：项目/文档/版本、片段定位、实体或敏感事实类型、来源层、简短判断依据、风险等级、建议动作、人工结论。依据是可核查的摘要，不记录或要求模型隐藏思维链。

实体合并优先确定的全文-简称定义和人工确认；同名、同址等弱关联只建议不强合。假名按项目稳定，映射原值加密，展示原值与恢复原值分别授权。

## 5. 路线比较与模块边界

| 路线 | 工作量/风险（相对） | 复用与适用性 | 决定 |
|---|---|---|---|
| A 模块化后端＋任务进程 | 中高/中；格式安全仍是主要工作量 | 复用既有 Presidio 评测与样本，业务模块可独立测试，安装组件少 | 已选择 |
| B 多服务平台 | 高/高 | 后续在实测瓶颈处拆服务，不提前复制部署与鉴权体系 | 暂不选 |
| C 浏览器优先计算 | 高/高 | 小文本可作为未来选项，不能解决全部大文档与私有模型部署 | 暂不选 |

网页端负责上传、状态、定位、复核和下载；不承担可信权限判断。业务后端负责身份、租户、项目、策略、映射授权及导出发布。任务进程负责解析、OCR、识别、生成与复查；模型适配器支持切换私有模型和外部 API。

存储职责：PostgreSQL 保存状态、任务表及审计索引；受控文件/对象存储保存原件、中间件和产物；独立 TS 任务进程处理持久化任务；密钥服务与密文分离。Node.js 服务框架及 OCR/NER/LLM 型号仍需 R0 验证。任务方案已选择 PostgreSQL 路线，是否复用兼容的开源队列库须单独确认，不能把该决定解释成已选 pg-boss。

现有 Presidio 保留为历史对照，不作为全 TS 业务栈的默认运行依赖。现有默认英文部署不能证明中文识别可用，且没有覆盖文件解析、文档回写、租户权限与安全导出。新方案分别验证中文模型、规则、许可证与接口，不强行复用不合适部分；不删除或停止用户既有部署。

任务状态：待处理、处理中、待复核、可导出、文件已生成待核验、下载校验中、已通过校验、失败、取消。状态机使用版本号和幂等键；本系统结果和映射不重复提交，但不保证外部提供方不重复消耗额度。用户允许结果未知的外部调用有限自动重试，必须记录每次 attempt、是否未知及潜在重复消耗，遵守重试总上限、授权有效期与账号限额；不能标成“确定未调用”。失去任务租约的旧进程不得覆盖新结果。取消、删除后禁止新派发、新产物被放行及新链接签发；已签发链接的访问边界另见下载规则。

## 6. 安全与放行规则

### 部署与外发边界

私有化：浏览器上传到企业服务器，核心处理可在内网完成。SaaS：服务方处理并保存材料，不宣称“本机离线”。两者都支持明确的数据保留策略。

私有模型模式为默认。外部 API 模式必须由管理员允许、项目授权，并在发送前展示提供方、字段/片段范围、用途和保留政策提示。先在受控域生成最小化副本；它依然可能含未识别秘密，不能以“已脱敏”绕过授权。高敏项目默认禁止外发；不得通过外部 OCR、嵌入、遥测或错误日志旁路发送原文。模型连接配置限制目标域名及内网地址，避免 SSRF；密钥仅服务器持有。

R1 外发授权由具有相应权限的用户在发送预览后显式确认，绑定批次、提供方/模型端点、用途、材料版本、片段内容哈希与有效期，不默认无限期授权整个项目。新增材料、提供方或片段变化须重新确认。任务在实际发送前再次校验授权与项目策略；撤销立即阻止未发送的请求，已发送内容无法保证追回，界面须如实显示。

### 放行条件

- 普通项：已配置类型、经校准阈值、无冲突且覆盖完整，可按策略自动处理；自动处理也需要通过产物复查。
- 强制复核：业务秘密、实体合并歧义、白名单与敏感命中冲突、模型不确定、OCR 改字影响定位、影响语义的金额日期处理。
- 硬阻断：解析/OCR失败、存在未处理页或对象、坐标缺失、必须识别层不可用、版本过期、产物复查失败。不得提供“忽略全部并安全导出”。
- 失败页可重试、补录覆盖或整页不可逆删除/遮盖；完成实际处理后重新检查才能解除阻断。处理报告列明删除与覆盖范围。

### 权限与生命周期

权限独立拆分：上传、查看原件、复核、导出脱敏件、查看映射、恢复真实值、管理模型与审计。组织管理员不默认等于可读所有原件；显式紧急授权需记录。租户/项目校验覆盖数据库、队列、缓存、对象、搜索、下载和还原接口。

原件、中间文本、OCR 缓存、映射、项目备份包均属于敏感资产，传输与静态加密；日志只记代号和诊断码。采用短时下载链接且禁止公开缓存：签发前重新校验权限、版本与实际产物；撤权立即阻止新链接签发，但已签发链接允许到期前继续访问，不能宣称即时撤销或追回已下载字节。链接须绑定唯一不可变对象，不允许覆盖同一路径后继续复用旧链接。密钥不得随密文包一同导出；忘记密码若能恢复，必须存在明确的授权密钥托管机制，不能暗设后门。

项目原件、已保存的 OCR/识别版本、映射、复核记录和产物默认持续保存，直到用户明确删除；不启用 30 天默认到期。执行时临时文件、队列运行记录与备份轮换不自动等同于项目档案，具体清理策略待确认，不据本设计清理现有材料。设置容量告警和可配置配额，达到上限阻止新上传而非删除旧材料。删除触发任务取消、对象/缓存/索引清理和映射清理。备份清除周期另行设定，界面区别“在线副本已删”和“备份等待到期”，不能承诺瞬时物理清除。文件预览禁用宏、脚本、外链与嵌入活动内容；解析进程隔离且限制 CPU/内存、压缩比、文件大小及页数。

## 7. 各格式导出契约

| 格式 | 输出规则 | 失败与降级规则 |
|---|---|---|
| DOCX | 替换底层文本，删除已遮盖内容；处理内嵌图；清理修订历史、批注与非必要属性 | 无法安全回写的对象阻断；允许用户选择经核验的扁平 PDF，不静默降级 |
| PDF | 真正删除文字/图像敏感区域，清理隐藏 OCR 层、注释、附件与增量历史；扫描页同步改像素 | 坐标错位或底层残留即失败；可选栅格化安全副本，明确失去可编辑性/部分可访问性 |
| 图片 | 改写像素并清除 EXIF 等元数据 | 不输出仅带可移除覆盖图层的原图 |
| XLSX | 首版采用明确标注的“值快照”，不保留可重算公式、外链或宏；处理隐藏工作表及对象 | 无可信公式缓存则阻断相关输出，要求上传重算后的副本；不在服务器执行不可信公式 |
| CSV | 保持行列与编码约定，单元格按策略替换；防止导出值被当作公式执行 | 明示前缀转义可能影响下游数值使用，原始值另在受控域保留 |
| Markdown/TXT | 替换正文、表格、链接目标及代码块中的敏感内容；图片只引用已处理副本 | 不携带原始 URL 参数、原件路径、文件名或嵌入原图 |

R1 的 XLSX 值快照不承诺保持计算能力；保留公式的安全回写是后续独立能力。外发包默认采用安全文件名，保留目录结构时也扫描路径名。产物与原件使用不同存储位置，禁止覆盖。

首版格式与处理方式组合如下。部分遮盖仍泄露部分字符，由策略决定是否允许；所有方式都先删除对应原始载荷，而非仅覆盖显示。

| 输出 | 假名/部分字符遮盖 | 区域遮盖或删除 | 授权还原 |
|---|---|---|---|
| DOCX | 支持文本；图片按区域处理 | 支持，底层内容清除后再画遮罩 | 仅明确的文本代号，不能恢复删除内容 |
| 文本 PDF | 支持，删除原文后放置代号；空间不足须调整或明确降级 | 支持真正删除区域内容 | R1 不直接还原 PDF；使用配套 MD/TXT 的代号回填 |
| 扫描 PDF/图片 | 支持区域清除后绘制代号；部分遮盖需确认字符坐标 | 支持像素改写 | 不还原像素；使用配套 MD/TXT 的代号回填 |
| XLSX/CSV | 支持单元格文本，XLSX 为值快照 | 清空或替换单元格值，不支持几何区域遮盖 | 支持单元格代号，不恢复公式 |
| Markdown/TXT | 支持 | 删除或置换文字，图片必须先处理 | 支持完整代号，不还原被删除段落 |

导出界面只能选择对应格式已支持的组合。降级到另一格式必须重新生成、复查并取得用户明确确认。不能因还原不支持而尝试模糊匹配真实值。

授权回填仅恢复明确假名映射，不恢复被不可逆删除的像素或泛化事实。用户导入外部 AI 的输出也视为不可信输入：不得执行内容指令；未知、冲突或被修改的代号报错。恢复结果属于含真实数据文件，另行预览确认，不自动推回外部 AI。

## 9. 阶段与验收

### R0：验证风险最高的组件

使用已有 8 份公开 PDF（619 页）验证解析与长文档行为；历史 Presidio 测试只覆盖前 7 份（575 页），新增尽调报告未测试，不能引用为新系统结果。另构造 DOCX/XLSX/CSV/MD/图片测试夹具，覆盖隐藏内容、修订、公式缓存、扫描错字、长实体和重复简称。私有原件未经授权不上传外部服务。

R0 必须证明各格式存在可用的提取—定位—回写路径，中文 NER 能运行，私有 L3 能处理约定场景。否则记录阻碍，不用模拟结果替代。产出选型、许可证检查、运行资源和代表性速度数据。

### R1：完整文档闭环

依次完成基础身份与存储隔离、解析锚点、三层识别与裁决、复核工作台、各格式副本与残留检查、映射还原、项目续接和备份、私有化发行。SaaS 与私有化共用代码，但 SaaS 公开上线必须额外通过租户与配额安全验收。

### R2：安全画像与背景补充

在可信环境先解析真实实体，按任务查询授权数据源，只返回必要属性、证据代号与时效。公网实名搜索会暴露查询主体，因此默认受限，不暗中联网。保留业务属性与关系不等于承诺匿名；组合属性可能反推出身份。需要精确身份判断的任务留在受控环境。

固定相同下游模型、提示词、任务与评分方法，对比原文、纯假名、假名＋画像三组。原文基线仅在获准环境运行。衡量正确性提升、关键结论变化、泄露/反推、耗时与成本，不仅衡量文本相似度。R2 成功阈值在标注试验前锁定，不能看到结果再修改。

### R3：企业运营增强

SSO/目录、席位运营、集中分发与专用内网更新、完整英文能力、经验证的扩容拆分。计费和支付渠道待商业方案确认，不阻碍首版试点。

### 必须通过的发布检查

以下是拟定验收门槛，不是当前成绩；完整文档批准后成为实现目标。

| 检查 | 门槛与测法 |
|---|---|
| 覆盖完整性 | 测试文件全部页/单元格/对象有处理或阻断状态，静默跳过为 0 |
| 固定格式识别 | 每类至少 100 个有效正例及 100 个干扰反例，召回≥99%、精确率≥98%；罕见格式单列不合并掩盖 |
| 中文 NER | 人/机构/地址分别至少 100 个标注实体，严格边界召回≥95%、精确率≥90%；按材料类型另报结果 |
| 语义识别 | 每类至少 50 正例与 50 反例，双人标注与争议裁决；风险检出召回≥90%，误报率≤15%，不确定项单列并须复核 |
| 产物安全 | 安全夹具中已批准隐藏的信息在解包、提取、复制、OCR与属性检查中残留为 0；未知秘密不宣称零泄露 |
| 一致性与还原 | 标注测试中同实体代号一致、不同实体不误合；授权代号准确还原，未知代号与越权还原拒绝 |
| 权限 | 跨租户/项目、队列、备份和回填越权拒绝；回收成员不得申请新链接，旧链接允许有效期内访问、到期必须拒绝；明确区分已接受的链接持有风险与新授权越权 |
| 恢复与幂等 | 上传中断、进程强停、模型超时、重复消息、取消与删除竞争均不假完成、不重复发布 |
| 版本有效性 | 修改原件、解析、策略或映射后，不允许旧复核状态授权新产物 |
| 外发 | 默认模式网络观察无文档外发；启用外部模式时发送内容与获准范围一致 |
| 可部署 | 新环境安装、升级回滚、备份恢复均有实际执行记录 |

测试集按文档/主体划分，避免相似模板同时进入调优与验收集。公开资料仅代表解析与标识测试，不覆盖真实业务秘密；另用受控或合成数据覆盖秘密场景。记录模型、规则、提示词、数据与标注版本，报告置信区间或样本量，不用总候选数充当准确率。

语义验收计分：确定命中、不确定、未命中三类结果均留在测试集。召回率分母是全部金标正例，正例上的不确定按未正确确定命中计；误报率分母是全部金标反例，确定误报计入分子，不确定另列。全体不确定率拟要求≤20%，并同时报告正反例不确定率、需复核候选数/百页与实测复核时间。人工确认后的成绩单列，不替代自动识别指标；不得以全部弃判通过验收。阈值与标注口径在调优和正式验收前锁定。

性能门槛待 R0 基准确定：必须注明 CPU/GPU、内存、扫描比例、页数和并发，记录排队、解析、三层识别、导出各阶段 p50/p95 与内存峰值；无硬件证据不承诺分钟级。高风险项目即使人工确认也不能绕过产物安全检查。

## 13. 工程选型讨论记录：私有模型与 TS 边界

本节保留此前选型讨论；最新审查状态、候选依据、任务及测试计划见 [工程评审](工程评审.md)。本节不是性能验证报告。第 12 节评分针对此前产品设计，不代表工程或实现质量评分。

### 模型开发路线建议

先以获准的公开/合成样本，通过 Codex CLI 使用用户的 ChatGPT 账号额度建立 L3 质量基线，再对同一标注集评估私有模型。保持任务、标签、上下文切分及评分一致；对运行引擎的比较尽量使用相同权重、精度和生成参数。更换模型导致的质量变化不能归因于运行引擎。

| 选项 | 官方能力依据 | 本项目建议与代价 |
|---|---|---|
| Ollama 本地模型 | [兼容接口](https://docs.ollama.com/api/openai-compatibility)、[结构化输出](https://docs.ollama.com/capabilities/structured-outputs) | 优先作为本机私有验证候选；需区分本地模型与云模型，不能因地址是 localhost 就认定未外发；不能把示例 API Key 当成鉴权 |
| llama.cpp server | [官方仓库](https://github.com/ggml-org/llama.cpp)提供多硬件推理与兼容接口 | 对量化、内存与 CPU/GPU 分配要求更细时评估；配置与模型文件管理成本高于简单拉取模型 |
| vLLM 服务 | [官方仓库](https://github.com/vllm-project/vllm)披露批处理、并行推理、结构化输出与兼容服务 | Linux GPU 服务器并发压力明确后再比较；用户已允许非 TS 独立引擎，但具体模型、硬件和部署尚未选定 |

本机只读检查：arm64、16 GiB 内存。尚未核验芯片型号、可用 GPU 服务器或剩余内存，不据此承诺某个模型大小一定可用。Linux 应用容器与 Mac 本机推理可以分开，不能假定容器自动获得与宿主机相同的推理加速。

L2 NER 与 L3 大模型分别评估。可研究 [Transformers.js](https://huggingface.co/docs/transformers.js/en/index) 的 token-classification/ONNX 路径，但仍需验证中文权重、tokenizer、实体边界、许可证和运行资源，不能以 JS 框架可运行推导中文识别达标，也不以 LLM 假装独立 NER 层。

所有模型调用都通过 TS 适配器：统一输入输出 Schema、超时、取消、有限重试、返回位置校验及费用记录。兼容接口不是完全相同的能力，逐提供方验证结构化输出、上下文限制和错误格式。JSON 合法不代表敏感事实判断正确。

### 已确认边界与待决事项

1. 已确认：自研前端、API、任务、规则和适配器全 TS，同时允许 Ollama/llama.cpp/vLLM 等独立引擎与原生/WASM 库；不自建 Python 业务服务。
2. PostgreSQL 队列继续保留用户选择：自建任务表与 TS 消费进程。可选替代是 [pg-boss](https://github.com/timgit/pg-boss) 等无 Redis 的现有队列；未获确认不切换。自建必须测试租约续期、超时接管、重试上限和旧进程写入隔离，数据库锁不能覆盖外部 API 的全部副作用。
3. 优先效果理解为暂缓注册、支付、订阅等商业化功能，保留最小身份/项目隔离；待用户纠正措辞理解，而非重新推翻功能规划。
4. 已确认：开发测试使用 Codex CLI 账号登录。本轮只核验安装、登录状态和官方文档，没有发起模型测试。测试时记录实际模型、推理设置、CLI 版本、提示词和数据集版本；触及限额暂停，不无限重试、不自动转付费 API。

### Codex CLI 开发测试适配器

2026-09-20 本机检查：`codex-cli 0.146.0`，`codex login status` 返回 `Logged in using ChatGPT`。官方说明 [codex exec](https://learn.chatgpt.com/docs/non-interactive-mode) 默认复用 CLI 登录，支持 JSON Schema 输出；[认证说明](https://learn.chatgpt.com/docs/auth)区分 ChatGPT 订阅访问与 API 按量访问。

- 由 TS 测试进程调用 `codex exec`，通过标准输入传样本，以 Schema 约束候选结果，再校验原文位置；结果不是直接可发布的脱敏文件。
- 初期串行、限量执行，设置超时及取消；固定配置，避免无关插件、检索或工具调用干扰识别评测。文件内容作为不可信数据，不执行其中的指令。
- 仅使用获准的公开/合成样本。账号登录的 CLI 仍调用云端模型，不是私有推理；私有材料须另行取得外发授权。只读沙箱不等于读取隔离，须限制可访问资料；临时会话也不等于服务端零保留。
- 账号凭据不写入仓库、日志、浏览器或产品镜像，不把个人账号作为正式 SaaS 多用户推理后端。正式私有推理与外部 API 继续走独立模型适配器。

### PostgreSQL 与 MySQL 比较及已确认选择

用户于 2026-09-20 确认保持 PostgreSQL + 独立 TS 任务进程，首版不引入 Redis，也不同时兼容两种数据库。这是需求适配判断，不是实测性能结论；本次仅确认并记录选型，尚未部署数据库。

| 关注点 | 比较与本项目选择依据 |
|---|---|
| 租户隔离 | PostgreSQL 原生 [RLS 行级安全策略](https://www.postgresql.org/docs/current/ddl-rowsecurity.html)可作为应用鉴权外的第二道防线。必须配置策略、非绕过角色及连接池的租户上下文；超级用户和 BYPASSRLS 角色可绕过，不能当作自动安全保障。 |
| 识别结果与证据 | PostgreSQL 的 [JSONB 与索引](https://www.postgresql.org/docs/current/datatype-json.html)适合候选实体、定位、模型证据等变化字段。核心权限、状态、版本与关联仍用有约束的关系表，不把全部业务塞进 JSON。 |
| 持久任务队列 | [PostgreSQL](https://www.postgresql.org/docs/current/sql-select.html)与 [MySQL 8.4](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)都支持 SKIP LOCKED；这不是 PostgreSQL 独占优势。二者都需实现租约、幂等、取消、故障恢复和并发测试。 |
| 运维与迁移 | 若部署方已有成熟 MySQL 团队或强制基础设施约束，MySQL 也是合理选择；目前没有这类已知约束，不为兼容两套数据库增加首版复杂度。 |

数据库主要保存任务、版本、复核决定、审计及受控映射索引；原始文件和导出产物使用受控文件/对象存储。换数据库不会直接提高正则、NER 或 LLM 的识别准确率，准确率取决于数据、模型、规则和验证流程。
