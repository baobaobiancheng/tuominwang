# 脱敏汪

TypeScript、PostgreSQL 和独立 worker 的电脑网页版脱敏工具。已接入规则识别、本地 NER/OCR、Word 原文预览、图像区域与文字复核、金额和专用场景规则、假名及批量还原、TMM 工程迁移、规则库与个人反馈、不可变复核快照和受权限控制的导出。算法结果始终需要人工复核。公开代码分析和我方流程测试，不等于竞品授权运行或实际业务准确率达标。

交付范围为电脑网页版。开发与浏览器验收以桌面操作为准，手机端不纳入本期开发和验收。

2026-10-13 基于 REA 的脱敏猫安装包分析，新增 7 类标识候选与当前材料的已知实体全文漏标检查。补录进入待确认草稿，沿用撤销、复核快照、项目假名及实际产物核验。接口、架构、证据和未对齐能力见 [REA 分析与开发对齐记录](文档/脱敏猫REA分析与开发对齐.md)。

## 本机启动

已有环境升级本版本时，先停止旧 API/worker，执行 `pnpm db:migrate`（增量迁移至 038），再启动。不要用旧 worker 处理新上传文件。

要求 Node 24 LTS、pnpm 11.21.0、Docker。应用与数据库只监听本机回环地址，不要把开发服务直接暴露到公网。

```sh
pnpm install --frozen-lockfile
pnpm setup
docker compose up -d --wait
pnpm db:migrate
pnpm admin:create --generate
pnpm models:ocr
pnpm dev
```

打开 <http://127.0.0.1:5178>。首次自动生成的管理员账号与随机密码保存在 `.data/开发登录.json`，仅当前用户可读；不要提交、截图或分享该文件。需要指定账号时使用 `pnpm admin:create`，该交互命令的密码输入会在终端显示，也可通过安全注入的 `ADMIN_USERNAME`、`ADMIN_PASSWORD` 提供。没有内置公共密码、注册或默认全项目管理员权限。

**已完成初始化的环境只需 `docker compose up -d --wait`、`pnpm dev`。** `pnpm setup` 拒绝覆盖 `.env`；迁移可重复执行；`admin:create --generate` 拒绝覆盖凭据。`.env` 丢失意味着加密资产可能无法恢复，请自行安全保管，本阶段不提供备份恢复功能。

登录后从侧栏新建或选择项目，在材料列表点击“导入材料”，上传文件或粘贴文本。打开材料后默认按类型和完整同值分组，可以选择实体组批量脱敏、保留或恢复待确认；逐处定位并切换“逐条复核”保留单处例外。全文查找支持全部文字、敏感标记内、敏感标记外，中央区域可切换原文审查和当前段落处理预览。仍支持选中原文补标、修改类型、撤销和重做。脱敏方式包括类型占位符、部分遮盖、自定义替换，以及需明确确认实体关系的项目假名。保存复核后生成处理副本，待任务完成再核验下载。原文不可变，复核保存增加版本；修改复核后旧产物不能获得新链接。

文件上传中断或刷新页面后，重新进入相同项目的“导入材料”，在“上传记录”中选择“继续上传”，补选原文件或原目录。服务端保留加密批次清单，前后端核对 SHA-256、路径及大小，跳过已保存文件；修改后的文件必须新建上传。浏览器不会在重启后自动取得本地文件权限，需要重新选择。续接单位为文件，尚未保存的单个文件会重新传输，不是分块断点续传。旧版未记录内容哈希的未完成批次不可自动续传，已保存的材料不受影响。

编辑复核时暂停后台刷新；保存、提交和读取文档期间锁定编辑与导航，避免覆盖新修改。多窗口版本冲突会保留当前草稿并提示重新载入，不自动合并或覆盖。下载请求必须携带当前页面的 `revision`；服务端发现版本变化时返回 `409 VERSION_CONFLICT`，不会静默下载其他版本。已签发链接的到期前可用规则不变。

前端采用统一深紫导航、浅色工作区、白底面板和类型语义色。文档审查使用材料导航、正文、敏感实体三栏，保留组织/项目权限入口。公开证据、实现差异及运行验证见 [脱敏猫工作流对齐](文档/脱敏猫工作流对齐.md)。

## 工程边界

- `apps/web`：React + Vite 工作台；`apps/api`：Fastify 会话、项目、复核、下载；`apps/worker`：独立 TS 持久任务进程。
- `packages/contracts`：Zod 输入契约及跨端类型；`packages/core`：规则、跨度校验与替换；`packages/adapters`：Drizzle/PG 事务、加密与文件存储。
- PostgreSQL 保存用户、项目、不可变文本密文、当前复核版本、任务、attempt、产物索引和审计。SQL 迁移位于 `scripts/001.sql`，Drizzle 执行参数化 SQL；不引入第二套 ORM 模型或 Redis。
- 不同账号默认不共享项目；组织管理员创建账号、管理角色和启停，项目成员逐项授权。原件、复核、导出、映射、还原、模型调用管理、成员管理、上传、词表和删除独立控制，组织管理员并不因此获得项目资料读取权。
- API/worker 数据库角色禁止超级用户和 BYPASSRLS；租户与用户上下文仅在事务内设置。调度器只有领取任务的受限数据库函数。`pnpm dev` 不向子进程传递迁移密码；单独 `pnpm api` / `pnpm worker` 是本机调试命令，加载完整开发 `.env`，不能直接当生产发行方式。
- 文本与产物使用 AES-256-GCM，原文绑定租户/项目/文档上下文；产物使用唯一 ID、独立路径和内容哈希。应用没有输出原文日志。数据库卷本身不做磁盘级加密，项目名称、状态和审计元数据仍可由数据库管理员读取。
- 下载前重新打开实际产物，验证版本、哈希和已选择隐藏值的残留；签发 5 分钟有效链接，旧链接到期前仍有效。再次下载仍检查实际文件完整性。没有“零泄露”或“三层安全脱敏”承诺。
- 后台重任务全局单槽，30 秒租约、1 秒心跳，失败最多执行 3 次；明确不可重试错误直接失败。CPU 处理在线程中运行，取消/失租会终止线程；SIGTERM/SIGKILL 与租约接管已做隔离回归。V8 堆限额不是进程 RSS 上限；本次部署按用户要求不新增容器资源限制，容量情况见部署实测记录。

## 验证命令

`pnpm check` 包含 11 条 Bend 法律与证明检查、13 个反向变异及生成产物一致性检查。需要本地 Bun，以及 `BEND_ROOT` 指向的锁定源码（默认 `../../bend`，即用户提供的 Bend checkout）；不会自动下载或跳过证明。业务运行使用已生成的 JS，不需要 Bend 常驻进程。方法及证明范围见 [Bend 方法与验证边界](文档/Bend方法与验证边界.md)。

```sh
pnpm check
# 修改 Bend 规则实现后，先证明再重新生成运行时模块：pnpm bend:build
# 集成测试会创建带 test- 前缀的账号和合成项目；不要与后台 worker 同时运行。
pnpm test:isolated
# 需要本机 Microsoft Edge；先停止本项目开发服务。测试自动建立隔离账号与数据库。
pnpm test:e2e:isolated
pnpm audit
```

端到端测试使用本机 Edge，不另下载浏览器；Linux CI 可调整 Playwright 的 `channel` 后安装对应 Chromium。测试只使用合成材料，包含本地 NER/OCR，不调用外部模型、不使用私有研究材料。测试产物与失败 trace 在忽略目录中；trace 可能含测试登录数据，不应共享。测试按真实登录限流节奏等待，不降低服务端限制。

`pnpm test:e2e` 和 `pnpm test:integration` 同样强制隔离。直接执行 Playwright 而未提供隔离数据库和测试账号时会拒绝启动，不能回退到 `.data/开发登录.json`。历史测试项目未因此被自动删除。

前端依据脱敏猫 0.5.9 的静态界面证据对齐深紫导航、浅紫工作区与三栏复核布局。保留本工具项目/组织权限和逐条处理决定，全文查找、批量复核与漏标检查在右侧切换；原文高亮不改动文本或标记偏移。分析依据、差异与对抗性审查见 [前端对齐记录](文档/脱敏猫前端对齐.md)。

## 当前实现与验证边界

- 全量规则清单、输入条件、优先级、遮罩、原版缺陷与我方安全差异见 [完整技术交接](文档/脱敏规则完整技术交接-迭代023.md)。逐接口事实与每次证据哈希见 [逆向台账](文档/逆向台账/README.md)。完整清单不代表算法已穷尽所有现实敏感信息。
- Markdown 使用原始字节、UTF-16 扫描文本和加密源码映射；保留可安全回写的语法。图片及原始 HTML 需明确确认移除；YAML 等隐藏语法存在选中信息残留时采用安全降级并核验。旧 Markdown 原始语法坐标必须重新识别；已签发的不可变下载链接仍遵守原有效期。
- Word 支持受控原版式浏览、常见 OOXML 文字对象、VML 和多帧内嵌图片；未知部件、未处理对象及不安全关系仍明确拒绝。XLSX 使用值快照。PDF/图片导出按复核后的页面策略实际改写像素，并重新核对文字与 RGB 像素；图片型输出会改变原格式能力，必须由用户选择。
- 支持矩形与椭圆区域、源实体类别及任意有效自定义类别；标注原文、类型和扩展元数据按文档上下文加密。跨页文字坐标查找使用真实 OCR 字符或词框，粗粒度词框的局部位置是估计值，仍需复核。
- 人脸、彩色/黑白印章、签名候选来自离线模型和算法。签名模型及字体单独按许可证、版本和 SHA-256 包装。视觉识别会漏检和误报；完整公开人脸框评估 5,749 张（原尺寸 1 张明确拒绝；严格 F1 76.05%）、签名测试及真实中文/英文 NER 报告保留全部样本、失败结果及训练数据重叠的不确定性，不能外推中文合同或全部业务文档。
- 已知密码的 PDF、Word/XLSX 解锁生成单独副本，不覆盖加密原件；不会破解未知密码。TMM 旧 ZIP、secure-v2 和 secure-v3 支持迁移和密码转移；原产品本机 keychain/master-key 必须通过合法导出取得，云端不伪造解封。导入后重新识别并人工确认，原审批不自动成为本工具审批。
- 项目映射表和 Word／Markdown 还原按源清单支持最多 100,000 条；合法 23 MB 长别名表经真实 worker 和下载验收，按完整文字查找树匹配，歧义编码变形明确拒绝；独立原值、类别与别名命名空间均保留。批量还原逐个真实文件处理，失败文件明确列出，不修改原件，不使用模糊猜测代替未知或歧义映射。
- 规则库、运行时名单及个人规则按真实来源与优先级消费；源已下线的自动学习接口保留为非活跃能力，不能声称模型正在学习。MCP 各工具按项目权限、材料版本和产物哈希执行；服务端不读取客户端任意本地路径。
- 保留组织和项目独立权限、AES-256-GCM、文件哈希、复核快照、任务租约、显式删除、下载有效期和现有文件/对象/页数预算。账号切换、跨标签页状态与过期复核仍有专门测试；不会自动批准待确认内容。
- 竞品未经授权的真实处理链保持未运行；桌面系统窗口、钥匙串、生物识别、本地更新器等与本项目电脑网页版存在平台差异。私有在线 AI 不在本次已接通能力中。

测试使用隔离账号、数据库及合成材料；公开真实语料单独标明许可证和领域。推荐使用与生产一致的 Node 24 运行验收。Node 26 曾出现测试业务完成后退出阻塞，历史失败日志保留。
